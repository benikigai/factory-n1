## Codex Sol (fast, precise, test-first)

**C1. Stage checkpoints and resume** (no model spend). This is MongoMation's pattern; see `docs/specs/factory-n1-research.md` §4 and their `apps/worker/src/harness/stages.ts`.
- `src/loop/checkpoint.ts`: after every generation, persist the loop state to `runs/<id>/checkpoint.json`:
  - generation, champion layout and evals, memory ops, accepted/rejected, curve;
  - seen layout hashes, stalled count, meter and call-guard counters, spend snapshot.
- Key it by a manifest hash of task, options, `git rev-parse HEAD` and `graderHash()`.
- On a rerun with the same `runId` and matching hash, resume at the next generation. On a mismatch, refuse.
- Add the git commit SHA to every `summary.json` and `results.json`.
- `scripts/memory-eval.ts`: skip pairs already present in `pairs.jsonl`.
- Hooking into `solve.ts`: send Claude a 5-line patch. Claude owns that file.
- **Done when:** an offline test kills a scripted solve mid-run, resumes it, and gets the identical final champion and artifacts.

**C2. Done Means Done goal compiler.** Spec §Decision 4; this is the biggest missing piece.
- **Goal Planner** (`nvidia/NVIDIA-Nemotron-3.5-Super-VL`): turns a one-line goal into typed checks over grader metrics (`src/sim/dod.ts` types), with schema validation and one repair.
- **Auditor** (`nvidia/NVIDIA-Nemotron-3-Super-120B-A12B`, a different Nemotron generation): vetoes weakened checks. Floor checks are always added in code.
- **Feasibility bounds:** code computes lower bounds (e.g. makespan ≥ last arrival + minimum service chain; receiving throughput). An infeasible goal yields `escalate` with the proof; a vacuous one is flagged.
- **Tighten-only lattice:** after audit, the DoD is hashed; any later edit must be strictly tighter.
- Tests offline with a mocked chat. Then **one live round** on 2 goals (one feasible, one deliberately impossible) under `CALL_BUDGET=8 SPEND_CAP_USD=0.05`. Save the evidence to `docs/evidence/goal-compiler.md`.
